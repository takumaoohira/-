# 東京スカイツリー散策（第2版：実データ版）

「東京スカイツリーと周辺地域の再現ゲーム開発指示書（仕様案 第1版）」と、2026年10月2日の改善依頼に基づくブラウザ用の一人称散策3Dゲームです。

- `index.html`：ゲーム本体（three.js r128 を CDN から読み込み）
- `data/`：実データ（建物・地図・航空写真）。**`index.html` と同じ場所に置いて、Webサーバー経由で開いてください**（ファイルを直接ダブルクリックするとブラウザの制限でデータを読めません。例：`python3 -m http.server` で起動して `http://localhost:8000/` を開く）
- `docs/`：修正前／修正後の画像、空中写真との比較画像
- `tools/`：データを作り直すためのスクリプト

### 2. スカイツリー本体

**資料で確認できた数値を反映しました。**
- 足元の正三角形：一辺約68m
- 心柱：直径8m・高さ375m（中に追加）
- 基部の鋼管：直径2.3m
- 天望回廊：直径約40m（半径19.4m→約20mに修正）
- 高さ634m、フロア340・345・350・445〜450、ソラカラポイント451.2m

**変えた見た目**
- 横方向の部材を「3段ごとに太い帯＋その間は細い部材」に変えました。単純な格子状だった印象を減らしています。

**未確認のまま**
- 鉄骨の本数や間隔の正確な値、展望台の窓割りは、図面や写真が取得できていないため模式のままです。

### 3. ソラマチ・スカイツリータウン

**棟の分け方**
- 外形は PLATEAU のものを使いました。
- 空中写真で次の5つの境界を確認し、棟に分けました：
  - ウエストヤード
  - タワーヤード
  - イーストヤード
  - イーストタワー
  - 屋上のプラネタリウムのドームと屋上緑地

**資料で確認できたこと**
- イーストヤードの最頂部が158m（イーストタワー31階）
- 売り場の階：ウエストヤード1〜4F、タワーヤード1〜3F、イーストヤード1〜7F
- 4F は屋外でつながっている
- スカイアリーナはウエストヤード4F

**推定**
- 各棟の高さ・段差・外壁は推定です。
- 外壁は「白いパネル＋各階のガラス帯」の素材にしました。第1版の青いガラスの箱はやめました。

**館内の上下移動**
- 1F→4F のエスカレーター・エレベーターは位置が確認できていません。そのため架空の階段は作らず、「館内移動（推定）」として場面切替で表現しています。第1版にあった推測の屋外大階段は削除しました。

### 4. 駅（別々に作り直し）

**とうきょうスカイツリー駅（高架）**
- 2本の線路は国土地理院のデータどおりの位置です。
- 線路の間の島式ホーム、ホーム中央の階段、地上の東改札口付近（推定）、北側の通りからタワーヤード北側入口までを、ひと続きで歩けます。
- 正面改札口・東改札口があることは資料で確認しました。ホームの形式と改札の位置は推定です。

**押上駅（地下）**
- B3 出口がイーストタワー地下3階と直結していることは資料で確認しました。そこで代表ルートは「改札 → 地下連絡通路 → B3 出口 → 館内移動 → 4F」にしました。
- A2 出口（浅草通り方面）は地上の位置が確認できなかったため、**作っていません**。
- 改札の位置、通路の形、台数は模式です。

### 5. 素材と光

**素材**
- **空の映り込み**：空を環境マップとして映り込ませ、ガラス・金属・塗装鋼の反射を素材ごとに変えました。
- **展望台のガラス**：透明度を上げ、外の景色が白っぽくならないようにしました。
- **地面**：空中写真に細かな凹凸の模様を重ねて、近くで見たときのぼやけを減らしました。明るさと彩度も調整しています。

**光**
- **夜の窓明かり**：強すぎる市松模様の発光を弱めました。
- **ソラマチの夜景**：ガラス帯を穏やかに光らせています。

### 6. カメラ

- 画角の初期値を水平65°にしました（第1版は75°）。
- マウスが動いていないときにも視点の角度が制限される不具合を直しました。

## 検査した内容と結果

| 項目 | 結果 | 方法 |
|---|---|---|
| 経路検査 | **126 / 126 区間で到達可能**（高・標準・軽量すべて） | ゲーム内の「検証 → 経路検査を実行」。徒歩区間は0.2m刻みで床と障害物を判定し、壁抜け・段差での引っ掛かり・床からの落下・入口が通れない箇所がないかを見る。エレベーター・館内移動は発着点の床を判定 |
| 空中写真との比較 | 3か所で同じ範囲を真上から比較 | `docs/aerial_vs_game_1〜3.jpg`。建物の外形・川の形・道路・高架・ドームの位置が一致することを目視で確認 |
| 修正前／修正後 | 4視点 | `docs/before_after_1〜4.jpg` |
| 起動・スクリプトエラー | エラーなし | ヘッドレス Chromium（ソフトウェア描画） |

経路の総数について：第1版の「170区間」は旧版の経路網の数です。今回は駅・通路・橋の位置を実データに合わせて経路網を作り直したため、区間数が126になりました。

### 未実施の確認（実施していないものを確認済みとはしていません）

- **地上からの現地写真との比較**：この作業環境ではウィキメディア・コモンズ、公式サイトの写真、地図サービスの写真を開けませんでした。そのため、人の目線での実写比較はできていません。12か所の比較視点（位置・方位・俯仰角・画角）は用意してあります。
- **実機での fps 測定・15分間の連続歩行**：GPU のある実機がないため未実施です。ゲーム内の F3 で、平均 fps、低下時の fps、メモリ、連続歩行の時間・距離を表示できます。
- **公式ページ本文の確認**：ブロックされていたため、数値は検索結果の要約から取りました（S11）。数値は正しい見込みですが、本文での照合はまだです。

## データの作り直し方（`tools/`）

1. `conv.py`：国土地理院のベクトルタイル（z16）をゲームの座標に変換する
2. `parse_plat.py`：PLATEAU の CityGML（タワーの周囲12区画）から、建物の外形と実測高さを取り出す
3. `fetch_far.py`：遠景用に、半径6kmと高層ビル群の区画を S3 から部分的にダウンロードする
4. `mosaic.py`：空中写真のタイル（z18・z16・z14）をつなげる
5. `build_assets.py`：`data/bldg.b64.txt`・`far.b64.txt`（建物の外形と高さを16bit整数で詰めてbase64にしたもの）・`world.json` を作る
6. `compose.py`：比較画像を作る
