# 東京スカイツリー散策（第3.2版：PLATEAU 2025・公式動線・質感強化版）

「東京スカイツリーと周辺地域の再現ゲーム開発指示書（仕様案 第1版）」と、2026年10月2日の改善依頼に基づくブラウザ用の一人称散策3Dゲームです。

- `index.html`：ゲーム本体（three.js r128 を CDN から読み込み）
- `data/`：実データ（建物・地図・航空写真。`l2.b64.txt` は PLATEAU 2025 の LOD2、`town.json` はスカイツリータウンの屋根面）。**`index.html` と同じ場所に置いて、Webサーバー経由で開いてください**（ファイルを直接ダブルクリックするとブラウザの制限でデータを読めません。例：`python3 -m http.server` で起動して `http://localhost:8000/` を開く）
- `docs/`：修正前／修正後の画像、空中写真との比較画像
- `tools/`：データを作り直すためのスクリプト

## 第3.2版で変えたこと（2026-10-03）：質感・通行人・車

### 質感（材質が伝わるように）
外部のテクスチャ配布サイトにはこの環境から接続できなかったため、すべて手続き的に自作しました（`tools/gen_tex.py`、`data/tex/`）。1つの素材につき「色」「凹凸（法線マップ）」「粗さ・金属感」の3枚を使い、光の反射の仕方まで素材ごとに変えています。

| 素材 | 使った場所 | 内容 |
|---|---|---|
| 舗石 | 4F スカイアリーナの床、入口棟の床 | 0.6×0.3m の石の馬目地、石ごとの色の差、目地のくぼみ |
| コンクリート | 高架の柱・桁、階段の側面など | 型枠の継ぎ目とセパ穴、雨だれのしみ、細かな気泡 |
| アスファルト | 車道、ホーム、地面（近く） | 骨材の粒と凹凸 |
| 塗装した鋼材 | タワー、手すり、鉄骨 | 塗装面のゆず肌と、わずかな光沢 |
| 外壁（マンション・事務所・カーテンウォール・ソラマチ） | 建物全般 | 窓ガラスは滑らかで空を映し、壁は粗い。窓のくぼみ・サッシ・バルコニー・パネルの目地に凹凸。夜の窓明かりは従来どおり |

**地面（航空写真）の見え方も変えました**
- 航空写真の明るさを、実際の路面の反射率の範囲（約3〜20%）に収めました。白く飛んで見えていた地面が、落ち着いた明るさになります。
- 近く（約180m以内）では、灰色の部分にアスファルトの粒、明るい部分に舗装の目地を重ねています。
- 画面全体の露出を少し下げました（0.85）。

### 通行人
- 円柱と球だった人を、胴・腰・頭・髪・首・腕（上腕と前腕）・脚（もも・すね）・靴に分けて作り直しました。
- 歩くときは、腰・膝・肩で手足を振り、上下にも揺れます。
- 体格（子ども・大人・高齢者）、上着・ズボン・スカート、肌と髪の色、鞄の有無を人ごとに変えています。立ち止まって周りを見ている人もいます。
- 人数と配置は演出です（実際の混み具合ではありません）。

### 車
- 箱を2つ重ねた形から、6車種の外形に作り直しました。セダン、軽自動車、ミニバン、タクシー、トラック、バスです。形は国産車の一般的な寸法の目安で、特定の車種ではありません。
- 窓ガラス、ライト、黒い樹脂部品、回転するタイヤとホイールを付けました。塗装には艶のある反射を付けています。
- 車間距離は車の長さに応じて取ります。

### 描画の重さ
- 通行人と車は、見えている分だけを描くようにしました。
- 初期視点での三角形数：高 約153万、標準 約110万、軽量 約60万。軽量では凹凸（法線マップ）を省いています。
- 経路検査は3画質とも170 / 170 区間で到達可能でした（変更後に再実施）。fps は GPU のない環境のため測れていません。

### 3. 駅から入口までの動線を公式の経路写真の順序に合わせた

- **とうきょうスカイツリー駅（東口・西口）**：改札 → 高架下 → タワーヤード 1F の「TOKYO SKYTREE」入口 → 館内エスカレーター → 扉から 4F スカイアリーナへ → 広場を東へ → 入口棟の MAIN ENTRANCE → チケットカウンター
- **押上駅**：改札 → 長いエスカレーターで 4F → ソラマチの通路 → 扉を出て左 → MAIN ENTRANCE
- **出口**：5F 出口フロア → 連絡ブリッジ → 東京ソラマチ「ソラフルパーク」（押上駅方面）

ゲームでは、屋外の部分（駅〜1F 入口、4F 広場〜MAIN ENTRANCE〜天望シャトル、5F〜連絡ブリッジ、ソラミ坂）はすべて歩けます。館内のエスカレーター部分だけは位置が分からないため、これまでどおり「館内移動（推定）」の場面切替です。

### 2. スカイツリー本体

**資料で確認できた数値を反映しました。**
- 足元の正三角形：一辺約68m
- 心柱：直径8m・高さ375m（中に追加）
- 基部の鋼管：直径2.3m
- 天望回廊：直径約40m（半径19.4m→約20mに修正）
- 高さ634m、フロア340・345・350・445〜450、ソラカラポイント451.2m

**変えた見た目**
- 横方向の部材を「3段ごとに太い帯＋その間は細い部材」に変えました。単純な格子状だった印象を減らしています。

**未確認のまま**
- 鉄骨の本数や間隔の正確な値、展望台の窓割りは、図面や写真が取得できていないため模式のままです。

### 3. ソラマチ・スカイツリータウン

**棟の分け方**
- 外形は PLATEAU のものを使いました。
- 空中写真で次の5つの境界を確認し、棟に分けました：
  - ウエストヤード
  - タワーヤード
  - イーストヤード
  - イーストタワー
  - 屋上のプラネタリウムのドームと屋上緑地

**資料で確認できたこと**
- イーストヤードの最頂部が158m（イーストタワー31階）
- 売り場の階：ウエストヤード1〜4F、タワーヤード1〜3F、イーストヤード1〜7F
- 4F は屋外でつながっている
- スカイアリーナはウエストヤード4F

**推定**
- 各棟の高さ・段差・外壁は推定です。
- 外壁は「白いパネル＋各階のガラス帯」の素材にしました。第1版の青いガラスの箱はやめました。

**館内の上下移動**
- 1F→4F のエスカレーター・エレベーターは位置が確認できていません。そのため架空の階段は作らず、「館内移動（推定）」として場面切替で表現しています。第1版にあった推測の屋外大階段は削除しました。

### 4. 駅（別々に作り直し）

**とうきょうスカイツリー駅（高架）**
- 2本の線路は国土地理院のデータどおりの位置です。
- 線路の間の島式ホーム、ホーム中央の階段、地上の東改札口付近（推定）、北側の通りからタワーヤード北側入口までを、ひと続きで歩けます。
- 正面改札口・東改札口があることは資料で確認しました。ホームの形式と改札の位置は推定です。

**押上駅（地下）**
- B3 出口がイーストタワー地下3階と直結していることは資料で確認しました。そこで代表ルートは「改札 → 地下連絡通路 → B3 出口 → 館内移動 → 4F」にしました。
- A2 出口（浅草通り方面）は地上の位置が確認できなかったため、**作っていません**。
- 改札の位置、通路の形、台数は模式です。

### 5. 素材と光

**素材**
- **空の映り込み**：空を環境マップとして映り込ませ、ガラス・金属・塗装鋼の反射を素材ごとに変えました。
- **展望台のガラス**：透明度を上げ、外の景色が白っぽくならないようにしました。
- **地面**：空中写真に細かな凹凸の模様を重ねて、近くで見たときのぼやけを減らしました。明るさと彩度も調整しています。

**光**
- **夜の窓明かり**：強すぎる市松模様の発光を弱めました。
- **ソラマチの夜景**：ガラス帯を穏やかに光らせています。

## データの作り直し方（`tools/`）

1. `conv.py`：国土地理院のベクトルタイル（z16）をゲームの座標に変換する
2. `parse_plat.py`：PLATEAU の CityGML（タワーの周囲12区画）から、建物の外形と実測高さを取り出す
3. `fetch_far.py`：遠景用に、半径6kmと高層ビル群の区画を S3 から部分的にダウンロードする
4. `mosaic.py`：空中写真のタイル（z18・z16・z14）をつなげる
5. `build_assets.py`：`data/bldg.b64.txt`・`far.b64.txt`（建物の外形と高さを16bit整数で詰めてbase64にしたもの）・`world.json` を作る
6. `compose.py`：比較画像を作る
7. `dl25.py`：PLATEAU 2025（墨田区）の CityGML から必要な3次メッシュだけを部分ダウンロードする
8. `parse_lod2.py`：CityGML から LOD2 の屋根面・壁面と LOD1 の外形を取り出す（`python3 parse_lod2.py <gmlをカンマ区切り> 2000 lod2all.json`）
9. `build_lod2.py`：LOD2 を三角形にして `data/l2.b64.txt`、スカイツリータウンの屋根面一覧を `data/town.json` に出力。続けて `build_assets.py` を実行すると、2025年度の範囲の 2020年度データが置き換わる
