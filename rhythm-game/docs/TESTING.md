# 動作確認の記録

## 自動テスト（`tests/run-tests.cjs`）
- 実行環境：Chromium（Playwright のヘッドレス版）、Linux。端末は 390×844 のタッチ対応として再現
- 結果：**28項目すべて合格**（詳細：`test-results.json`、`test-log.txt`）

| 確認内容 | 3ゲームの結果 |
|---|---|
| 正解時刻ちょうどに入力 → 100点・全Perfect | 合格（もちつき27／ペンギン24／エコー32 対象） |
| 曲の最後まで、映像用の時計と音声出力の時計の差が8ms未満、予約が遅れた音0件 | 合格（最大 0.6〜3.9ms） |
| 毎回 +35ms 遅れて入力し、入力の補正を +35ms → 全Perfect（補正が正しい向きに効く） | 合格 |
| 補正なしで +75ms 遅れ → 全Good（60点）、「遅れて押す傾向」のアドバイス | 合格 |
| 2秒ごとに主スレッドを250ms止める（描画の遅れ） → 判定がずれない | 合格 |
| 入力なし → 0点・全Miss | 合格 |
| 60msごと・250msごとの連打 → 0点 | 合格（余分な入力 711回／157回） |
| 開始ボタンを3回同時に押す → 動くセッションは1つ | 合格 |
| 6回続けて再挑戦 → 1回の入力で記録は1件、前のセッションの音は停止 | 合格 |
| Spaceキーの長押し → 入力1回 | 合格 ※ |
| 画面タップ → 入力1回（click 等と重複しない） | 合格 |
| 一時停止ボタン → 判定に入らず一時停止 | 合格 |
| バックグラウンドへ移動 → 中断 → 再開で最初（カウント）から | 合格 |
| 練習を最後まで（1回目はわざと失敗） → 同じ課題を繰り返し、練習完了・保存 | 合格 |
| 再読み込み後も、補正値と最高スコアが残る | 合格 |

※ 初回の全体実行では、直前のボット入力から5ms後にキーを押していました。そのため「25ms以内の重複入力は無視する」処理にかかり、不合格になりました。これはテストの書き方の問題です。テストに待ち時間を入れて再実行し、合格を確認しました。

主スレッドを止めるテストで、止まった直後に映像用の時計が音声の時計から最大19msずれることが分かりました。そこで「8ms以上ずれたら即座に合わせる」ように修正しました。修正後に月面もちつきの全項目（16項目）を再実行し、すべて合格しました。
