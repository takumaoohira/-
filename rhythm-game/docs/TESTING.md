# 動作確認の記録

## 自動テスト（`tests/run-tests.cjs`）
- 実行環境：Chromium（Playwright のヘッドレス版）、Linux。端末は 390×844 のタッチ対応として再現
- 結果：**55項目すべて合格**（5ミニゲーム × 本編・ハード。詳細：`test-results.json`、`test-log.txt`）

| 確認内容 | 結果 |
|---|---|
| 正解時刻ちょうどに入力 → 100点・全Perfect（本編・ハード） | 5ゲームとも合格 |
| 曲の最後まで、映像用の時計と音声出力の時計の差が8ms未満、予約が遅れた音0件 | 合格（最大 0.5〜7.0ms） |
| 毎回 +35ms 遅れて入力し、入力の補正を +35ms → 全Perfect（補正が正しい向きに効く） | 合格 |
| 補正なしで +75ms 遅れ → 全Good・「遅れ」の助言／ハードで −75ms 早め → 全Good・「早め」の助言 | 合格 |
| 2秒ごとに主スレッドを250ms止める → 判定がずれない | 合格 |
| 本編・ハードの全10譜面の検証（入力どうしのGood範囲が重ならない、荷物が重ならない、卓球の返球が間に合う） | 合格 |
| ハードの最高スコアは本編と別に保存 | 合格 |
| 入力なし → 0点／60msごと・250msごとの連打 → 0点 | 合格 |

| 再読み込み後も補正値と最高スコアが残る | 合格 |

### 途中で見つけて直したこと
- 月面もちつきのハード（BPM126）で、譜面の検証に「入力が近すぎます」と出ました。2連続の間隔は半拍＝238msです。検証の基準を、固定の240msから「隣どうしのGood範囲（±100ms）が重ならない＝200ms超」に改めました。あわせて、45秒に届かなかったハード譜面2つ（もちつき・卓球）を2小節ずつのばしました。再実行して、どちらも100点・Perfectのみを確認しました（+40msずらしても100点）。
- 主スレッドを止めるテストで、止まった直後に映像用の時計が音声の時計から最大19msずれました。8ms以上ずれたら即座に合わせるように直しました（初期版で修正済み）。
- ログに出る `ERR_CERT_AUTHORITY_INVALID` は、テスト環境の通信制限で見出しフォント（Google Fonts）を読めなかったためです。この場合は端末の太字フォントで表示されます。ゲームの動作には影響しません。
