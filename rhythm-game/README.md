# リズムびより（初期版）

音を聴いて、拍を数えて、画面のどこかをタップするだけのリズムミニゲーム集です。
「リズム天国」のような遊び方（キャラクターの動きと音の合図からタイミングをつかむ）を目指した、**オリジナル**の作品です。キャラクター・曲・効果音・名称はすべて新しく作りました。

| ミニゲーム | ルール（音だけで遊べる） | BPM |
|---|---|---|
| 🌕 月面もちつき | 「トン・トン」→ 3拍目でタップ。「トン・カッカッ」→ 3拍目とその裏で2回 | 104 |
| 🐧 ペンギン宅配便 | ベル「チリーン」→ 2拍あと。笛「ピピッ」（速達）→ 1拍あと | 100 |
| 🐰 森のエコー楽団 | 先生の「ポン」を1小節聴いて、次の小節で同じリズムを返す | 96 |

---

## 1. 起動方法

### いちばん簡単な方法
`rhythm-game/index.html` をブラウザで開くだけで遊べます。ビルドは不要で、外部ライブラリや外部ファイルも読み込みません。

### 1ファイル版（配布・実機確認用）
`dist/rhythm-biyori.html` は、CSS と JavaScript をすべて埋め込んだ1つのファイルです。メールやチャットで送って、そのまま開けます。ソースを変更したら次のコマンドで作り直してください。
```bash
node tools/build-single.cjs
```

### スマートフォンで遊ぶ（同じWi-Fiのパソコンから配信）
```bash
cd rhythm-game
python3 -m http.server 8000
# スマートフォンのブラウザで http://<パソコンのIPアドレス>:8000/ を開く
```
- **最初に「タップしてはじめる」を押してください**。スマートフォンのブラウザは、画面を触るまで音を出さない仕組みのためです。
- iPhone はマナーモードだと音が出ないことがあります。iOS 16.4 以降は、マナーモードでも鳴るよう設定しています。

### 操作
- **タップ**：画面のどこでも反応します（片手で遊べます）
- **PC**：スペースキーでも同じ操作ができます。Esc で一時停止、Shift＋D で確認用表示の切り替え
- 一時停止ボタン（左上の「Ⅱ」）は小さく、誤って押しにくい隅に置いています。ボタンを押しても判定には入りません

## 2. 開発環境と採用理由

**HTML＋JavaScript＋Web Audio API＋Canvas 2D（ビルドなし・依存なし）**

- **音と入力を同じ時計で扱える**：Web Audio の時計（`AudioContext.currentTime`）は、音声ハードウェアのサンプル単位で進みます。曲・合図・成功音をすべてこの時計の時刻を指定して予約するため、フレーム落ちしても音の位置がずれません。
- **入力時刻を精密に取れる**：`getOutputTimestamp()` で「今スピーカーから出ている音の時刻」と `performance.now()` の対応を取り、タップイベントの `timeStamp` を同じ時間基準に変換して判定します（出力遅延も含めて換算）。
- **インストール不要で実機確認できる**：スマートフォンのブラウザでそのまま動き、PCでも同じ物で確認できます。
- **素材の権利で困らない**：音はすべてプログラムで合成し、絵はすべて Canvas で描いています。

## 3. 遊びの流れ

タイトル → ミニゲーム選択 → 練習 または 本編 → 結果（「もう一度」「選択画面へ」）

- 3種類とも最初から選べます。
- 練習していないミニゲームで本編を押すと「練習してから遊ぶ？」と一度だけ確認します（「練習せずに本編へ」も選べます）。
- 本編は 55〜65秒です。開始前に4拍のカウントがあり、ミスしても最後まで遊べます。最後は全員の動きと和音がそろう締めの演出で終わります。

### 練習モード
- 「お手本（自動演奏）×2 → きみの番」の順で教えます。説明文は短い一言だけです。
- 1つの課題で扱うリズムは1種類です（ペンギンの課題3「まぜて配達」だけは、習った2種類を順に並べた復習用です）。
- 失敗すると、同じ課題をすぐにもう一度やります。**2回連続で成功**すると次の課題へ進みます。4回連続で失敗したときは、お手本をもう一度見せます。
- 入力するたびに「早い」「ぴったり！」「遅い」を下に表示します。試行が終わるごとに「ちょっと早かった！」「押し忘れがあったよ」などの短いコメントも出します。
- 右上の「スキップ」でいつでも抜けられます。一時停止メニューから「次の課題へ」も選べます。選択画面からいつでも練習し直せます。

## 4. 同期の仕組み（最優先した部分）

```
           ┌──────────── AudioContext の時計（唯一の基準） ────────────┐
譜面(拍) ─→ 秒 ─→ 先読みスケジューラ（25msごと／0.25秒先まで予約）─→ 音
タップ.timeStamp ─→ heard時刻 ─→ 曲の再生位置 −「入力の補正」 ─→ 判定
毎フレーム: heard時刻 ─→ 曲の再生位置 −「映像の補正」 ─→ 拍 ─→ 描画
```

- 曲の開始時刻 `startAt` を1回決めたら、合図・判定・アニメーションはすべて「曲の再生位置」から計算します。フレーム数や `setTimeout` の積み重ねは使わないので、後半になってもずれが蓄積しません。
- 押し忘れの判定（期限切れ）は「前のフレームの時刻」で行います。主スレッドが一時的に止まっても、その間に溜まったタップが先に処理されます。
- 音素材は、再生前にすべて合成・読み込みを済ませてから開始します。
- 再挑戦・中断のときは、セッション専用の出力をまとめて切断します。予約済みの音も消えるので、音が重なりません。
- アプリがバックグラウンドへ移動したとき（`visibilitychange`／`pagehide`／音声の中断）は、自動で中断します。復帰後は「最初から（カウント付き）」で再開します。

## 5. 判定とスコア

| 判定 | 条件（初期値） |
|---|---|
| Perfect | 正解時刻との差が ±50ms 以内 |
| Good | ±50ms を超え ±100ms 以内 |
| Miss | ±100〜150ms の入力（早すぎ・遅すぎ）、または押し忘れ |
| 余分な入力 | 判定対象のない時間のタップ（1回 −1点、コンボが途切れる） |

- 1回の入力で成功にできる対象は1つだけです。範囲内に複数ある場合は、未判定のうち一番近いものに対応させます。1つの対象を二重に採点することもありません。
- カウント中、お手本中、エコー楽団の「聴く」小節、締めの演出中のタップは減点しません。
- タップは `pointerdown` だけで受け付けます（click／touchend は使いません）。そのため、タッチとクリックの二重入力は起きません。25ms以内の重複入力とキーリピート（長押し）も無視します。
- スコア：`100 ×（Perfect ＋ Good × 0.6）÷ 全判定対象数 − 余分な入力数` を 0〜100 に収め、四捨五入して表示します。
- 評価：90以上「大成功！」／75〜89「いい感じ！」／60〜74「クリア！」／59以下「もう一度！」（60点以上で「クリア」として保存）
- 結果画面のアドバイス：判定のずれが8件以上あるときだけ、平均と、ばらつき（標準偏差）から傾向を出します（平均±18msを超えると「早め／遅め」）。押し忘れが多いときと、余分な入力が多いときも一言出します。

## 6. 変更方法（リズム・判定幅・BPM）

### リズムパターン・本編の並び・BPM：`js/games/<ゲーム>.js`
```js
const BPM = 104;                       // テンポ
const patterns = {
  A: { len: 4,                         // 長さ（拍）
       cues:   [{ b: 0, type: 'ton', who: 'a' }, { b: 1, type: 'ton', who: 'b' }],  // 合図の拍位置と種類
       inputs: [{ b: 2, type: 'hit' }] },                                          // 入力の拍位置
  fin: { len: 4, end: true, fx: [{ b: 0, type: 'finale' }] }                       // 演出の種類
};
const main = [ { p: 'count', sec: 'count' }, { p: 'A', sec: 'A', guide: '上部の案内' }, ... ];
```
- `offset`：楽曲開始オフセット（秒）。録音した曲に差し替えるときに使います。
- `cueSounds`：合図の種類 → 音色。`music()`：小節ごとの伴奏。`lessons`：練習の課題。
- 判定処理（`js/judge.js`）は「秒に変換された入力位置」だけを見ます。曲やリズムを変えても、判定処理を書き換える必要はありません。
- URL に `?dev` を付けて開くと、譜面の検証結果（入力どうしが近すぎないか、荷物が重ならないか）をコンソールに出します。

### 判定幅・スコア・評価：`js/config.js`
- `judge.perfectMs` / `goodMs` / `captureMs`、`score.goodWeight` / `extraPenalty`、`ranks`、`advice`、`practice.needStreak` など。
- 判定幅と余分な入力の減点は、設定画面の「開発者向け」でも変更・保存できます（試遊しながら調整するため）。

## 7. 設定・タイミング調整

- **音量**：全体／BGM／合図／効果音を、それぞれ個別に調整できます。
- **入力の補正**（判定だけに効く）：音より遅れて押してしまう → ＋、先に押してしまう → −。
- **自動調整**：一定のテンポの「カッ」に合わせて20回タップします（最初の4回は聴くだけ）。最初の2回は慣らしとして除き、残りのずれの中央値を目安として表示します。「この値にする」で保存します。
- **映像の補正**（見た目だけに効く）：音と同時に床に着くボールを見て、ずれていれば ±10ms ずつ合わせます。判定には影響しません。
- 補正の向きは自動テストで確認済みです。「+35ms遅れて押す人」が補正+35msにすると、全部 Perfect になります。
- **振動**（対応端末のみ）と**画面の揺れ演出**は、それぞれオフにできます。
- 音声機器が変わったことを検知したら、再調整をすすめるメッセージを出します（ブラウザが検知に対応している場合）。
- 最高スコア・クリア状況・練習済み・音量・補正値は、端末内（localStorage）に保存します。再起動しても残ります。

### 開発中の確認機能
設定 →「開発者向け」→「確認用の表示」、または PC で Shift＋D を押します。曲の現在時刻、拍、次の対象の時刻、実際の入力時刻、正解との差（ms）、判定結果、余分な入力の記録、音声の遅延情報を、プレイ画面の右上に表示します。

## 8. 使用素材と入手元・利用条件

| 種類 | 内容 | 入手元・利用条件 |
|---|---|---|
| 曲（3曲） | 旋律・和音・リズムを `js/games/*.js` に記述し、`js/synth.js` で合成 | 本プロジェクトで新規作成 |
| 効果音・合図 | トン・カッ・チリーン・ピピッ・ポン・ペタン ほか（`js/synth.js`） | 本プロジェクトで新規作成（波形をプログラムで生成） |
| キャラクター・背景 | 宇宙人、ペンギン、うさぎ、リス、フクロウ、カエルなど（Canvas で描画） | 本プロジェクトで新規作成 |
| フォント | 端末に入っているフォント（ヒラギノ丸ゴ、BIZ UDPゴシック、メイリオ など） | 外部フォントは読み込まない |

外部の画像・音声・ライブラリは使っていません。

### 仮素材について
曲・効果音は、すべて**プログラムで合成した仮素材**です。プロの作曲・録音素材に差し替える場合：
- 合図・効果音：`RG.Audio.buffers.set('音色ID', AudioBuffer)` で同じIDに登録すれば、譜面・判定はそのまま使えます（例：`ton` / `ka` / `bell` / `whistle` / `pon` / `slap` / `catchBox` / `tan` / `miss` / `drop` / `kazoo`）。
- 曲：各ゲームの `music()` を空にします。代わりに、録音した曲を `startAt` の時刻に1つの音源として予約し、曲の頭から1拍目までの時間を `offset` に入れてください。

## 11. 確認した環境・既知の問題

### 確認した環境
| 環境 | 結果 |
|---|---|
| Chromium（Playwright ヘッドレス、Linux）／縦 390×844・360×640・横 844×390・PC 1280×720 | 自動テスト・画面確認とも問題なし |

### 未確認の環境（実機での操作感は未確認です）
- **iPhone（Safari）・Android（Chrome）の実機**：開発環境に実機がないため、**タップの手応えや音の遅れは未確認**です。最初に実機で、自動調整の値（ふつうのスピーカーなら ±30ms 程度の想定）と、合図の聞き取りやすさを確認してください。
- Firefox、デスクトップ Safari、Bluetooth イヤホン

### 既知の問題・制限
- Bluetooth イヤホンは、ブラウザに報告される遅延が実際と違う機種があります。その場合は「入力の補正」と「映像の補正」の両方で合わせてください。
- `devicechange`（音声機器の変更の検知）は、ブラウザによっては通知されません。設定画面に、機器を変えたら再調整するよう案内を書いています。
- 振動は Android Chrome などの対応端末だけで動きます（iPhone は非対応）。
- ヘッドレス環境では実際に音を聴けないため、音量バランスは書き出した波形の測定（ピーク・合図とBGMの音量差）で確認しました。耳での最終調整が必要です。
